# SIME 性能白皮书（机制与基准）

> 原则：**每一个性能声明都有机制依据和可复现基准**，禁止无口径的参数广告。
> 本文对应内核 v2（增量聚合机制），基准工具 `core/src/scripts/bench.ts`（sime-bench 种子版）。

## 1. 基准结果（当前版本）

口径：确定性事件预生成（50% 认证失败 / 30% 网络连接 / 15% Web / 5% 工控指令），
计时仅含 feed/求值热路径，单进程 Node 22，10 条规则全量编译加载。

| 环境 | S1 规则引擎 feed | S2 适配器解析+映射 | 备注 |
|---|---|---|---|
| **Linux 实测（Debian 12, 4C/7.7G, Docker 容器）** | **192,226 events/s** | **202,400 events/s** | 2026-09 实测，生产部署形态 |
| Windows 开发机实测 | ~224,000 events/s | ~234,000 events/s | 参考值 |

**实测部署记录（2026-09）**：Debian 12 / 4C / 7.7GiB / Docker 29.8，`docker compose up -d --build`
一体化部署（core + PostgreSQL），容器常驻内存 **38.67 MiB**（core）+ 19.45 MiB（PG），空载 load 0.06；
同机 55 条攻击事件回放命中 6 条规则、告警落 PostgreSQL（pgProfile: active）。

复现：`cd core && npm run bench`（`--quick` 减量）。CI 中 `npm test` 内置 5,000 EPS 性能地板，
低于地板即失败——**性能回归按正确性同等对待**。sime-bench 完整版随 M3 发布。

## 2. 机制优化清单（v2 内核，"优化到机制"的落地）

| # | 机制 | 替代的naive实现 | 复杂度变化 |
|---|---|---|---|
| 1 | **增量滑窗聚合**：1 秒粒度桶 + 窗口总量，事件到达即判定谓词入桶，过期桶剪枝回减 | 每事件全窗口重扫求聚合 | O(window) → **O(1)** |
| 2 | **引用计数增量去重**：count_distinct 用全局值引用计数表 + 桶级增量，剪枝回减，值归零即退出 distinct 集合 | 求值时合并全部活跃桶的 Set | O(桶×值) → **O(1)** |
| 3 | **序列状态机**：sequence 步骤事件驱动推进（当前步 + 首末时间戳） | 每事件贪心扫描全窗口 | O(window×steps) → **O(1)** |
| 4 | **AST 类别预过滤**：编译期从合取链推导 event.category 约束集（含 or/not/seq 时自动放弃，保证不漏报），不相关事件整规则跳过 | 每事件过全部规则 | 规则数 × 命中率 相关 |
| 5 | **点路径分词缓存**：规则路径集合有限，split 一次永久缓存 | 每次访问 split | 分配次数 → 0 |
| 6 | **适配器 compile-once**：kv 模板编译为正则、mapping 编译为解析器闭包，均在加载期 | 每事件重建正则/逐条解释 | 每事件 0 次编译 |
| 7 | **冷却去重**：同规则同分组一个窗口周期只出一条告警 | 告警风暴 | 告警量 ↓ 窗口倍数 |
| 8 | 优雅退出（SIGTERM → 停收流 → 刷缓冲）| 直接 kill | 滚动重启零丢事件 |

## 3. 同配置对标口径（如何理解"比其他设备强"）

| 配置 | SIME 目标（v2 内核，单进程） | 说明 |
|---|---|---|
| 2C4G | ≥ 100,000 EPS + 平台全部功能 | 社区版开箱档；市面同类监控/SIEM 一体机普遍 16C 起步 |
| 8C16G | ≥ 500,000 EPS（含 PG 持久化） | 中型企业档 |
| 集群 | 5,000,000 EPS（多进程 + Kafka/Flink 后端，M3） | 超大量级档 |

对标方法学：
- 与日志易 Beaver"每秒检索 100 亿条"的关系：那是**检索**口径（已在索引上查询），SIME 的 S1 是**接入+检测**口径（写入路径实时计算）——两者不冲突，M3 阶段分别发布检索与接入双基准；
- 所有数字附硬件规格、事件构成、命令行，`sime-bench` 一键复现；
- 对比测试必须同机同配同数据集，sime-bench 的数据生成器公开，欢迎第三方复测。

## 4. 下一层机制路线（v3，超前性预留）

1. **多核分片**：worker_threads 按 device_id 哈希分片，SharedArrayBuffer 共享窗口状态，线性扩展到全核；
2. **零拷贝接入**：Agent（Fluent Bit 大改）→ 内核走共享内存环形缓冲（同机），替代 JSON 序列化；
3. **SIME-TS 统一存储**（Arrow/DataFusion 大改）：检索与聚合下沉列存，机制见蓝图 §6.3；
4. **PG 摄入走 COPY 二进制协议**：告警批量落库吞吐 ×10；
5. **io_uring**（Linux 5.1+）：日志文件采集与冷数据回灌的 IO 路径。

## 5. 已知边界（诚实清单）

- S1 基准未含网络栈与磁盘 IO（接入面的网络吞吐在 M1 接入层落地后并入基准）；
- 单进程内存状态有上限（桶数 ≈ 窗口/1s × 分组数），超大规模依赖集群分片（M3）；
- Node 单进程对 CPU 密集解析有上限，~500k EPS 后必须多核分片（v3-1）。
